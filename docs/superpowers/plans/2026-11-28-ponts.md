# Ponts au-dessus des enclos — plan de construction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un outil « Pont » qui trace librement un pont au-dessus d'un ou plusieurs enclos, raccordé aux allées, où les visiteurs passent et s'arrêtent pour regarder les monstres.

**Architecture :** une case de la grille reçoit un champ `bridge` (l'id du pont, ou `null`) ; elle reste à son enclos (`occupant`) pour les monstres et devient marchable pour les visiteurs et le personnel. Les règles du tracé sont des fonctions pures dans `src/sim/bridge.js` ; `Builder.placeBridge` les applique. La scène 3D construit tablier, rambardes, piliers et escaliers en géométrie, et élève les visiteurs selon `bridgeHeightAt`.

**Tech Stack :** JavaScript (modules ES), Vite, Vitest, Three.js, Phaser (scène de jeu cachée qui fait tourner les outils).

**Spec :** `docs/superpowers/specs/2026-11-28-ponts-design.md`

## Global Constraints

- Tous les textes visibles en français, dans `src/i18n/fr.js`, sans caractères cassés (test `i18n-coverage`).
- Les commentaires du code restent en anglais, comme dans le reste du projet.
- Une ancienne sauvegarde (cases `[ground, occupant]`) se charge sans pont.
- `BALANCE.bridgeCostPerTile = 50` (5 × `pathCost`), `BALANCE.bridgeViewBonus = 0.25`.
- Remboursement à la démolition : `BALANCE.demolishRefund` (comme le reste).
- Pas de ponts croisés ni superposés ; pas de pont ailleurs qu'au-dessus d'enclos.
- Note : la scène Phaser 2D est cachée (elle ne fait que porter les outils) ; le dessin du pont n'est fait qu'en 3D. *(Écart avec le spec, qui prévoyait un dessin 2D : il n'y a plus de vue 2D affichée.)*

## Review Focus

1. **Un visiteur déjà sur un pont quand on le démolit** : il ne doit pas rester bloqué dans l'enclos — il repart vers une allée (comme quand une allée sous lui disparaît). → test dans la tâche 3.
2. **Démolir l'enclos sous un pont** : le pont disparaît d'abord (remboursé), aucune case ne garde un `bridge` orphelin. → test dans la tâche 3.
3. **Fusion de deux enclos dont l'un porte un pont** : les cases gardent leur `bridge`, les visiteurs passent toujours. → test dans la tâche 3.
4. **Tracé qui repasse sur lui-même ou fait demi-tour** : revenir sur l'avant-dernière case retire la dernière ; une case déjà dans le tracé plus loin en arrière n'est pas rajoutée. → test dans la tâche 2.
5. **Le personnel (gardiens)** traverse les ponts sans s'y arrêter comme s'ils étaient dans l'enclos, et `findNearest` vers une allée accepte une case de pont. → test dans la tâche 1.

### Task 2 : règles du tracé (fonctions pures)

**Files :**
- Create : `src/sim/bridge.js`
- Modify : `src/config/balance.js` (`bridgeCostPerTile: 50`, `bridgeViewBonus: 0.25`, `bridgeDeckHeight: 3.9`)
- Test : `tests/sim/bridge.test.js`

**Interfaces :**
- Produces :
  - `extendTrace(trace: {tx,ty}[], tile: {tx,ty}): {tx,ty}[]` — nouvelle liste : `tile` ajoutée si voisine (4) de la dernière ; si `tile` est l'avant-dernière, la dernière est retirée ; si `tile` est déjà dans le tracé ou pas voisine, tracé inchangé ; tracé vide → `[tile]`.
  - `checkBridge(grid, builder, trace): { ok: true, deck: {tx,ty}[], paths: {tx,ty}[], cost: number } | { ok: false, reason: string, bad: {tx,ty}[] }`. `deck` = cases du tracé dans un enclos ; `paths` = cases d'herbe libre du tracé (à poser en allée). Raisons, dans cet ordre : `bridgeTooShort` (moins de 3 cases), `bridgeNoEnclosure` (aucune case d'enclos), `bridgeEnds` (le premier ou le dernier n'est ni allée ni herbe libre), `bridgeBlocked` (une case hors enclos qui n'est ni allée ni herbe libre, ou une case d'enclos déjà pont, avec un abri (`builder.shelterAt`), ou une décoration non `low`). `cost = deck.length × bridgeCostPerTile + paths.length × pathCost`. `bad` : les cases fautives, pour l'aperçu rouge.
  - `bridgeHeightAt(grid, x, y): number` — hauteur (m) d'un point en coordonnées de cases (continues) : `bridgeDeckHeight` sur une case de pont ; sur une case non-pont voisine (4) d'une case de pont (l'escalier), monte linéairement de 0 (bord opposé) à `bridgeDeckHeight` (bord commun) ; sinon 0.

- [ ] **Step 1 : tests qui échouent** (`tests/sim/bridge.test.js`, grille 20×20 + `Builder`) :
  - `extendTrace` : ajout d'un voisin ; demi-tour retire la dernière ; case non voisine ignorée ; case déjà dans le tracé ignorée.
  - `checkBridge` valide : allée (2,5), enclos 3..6 × 4..6, allée (7,5) ; tracé (2,5)…(7,5) → `ok`, `deck.length === 4`, `paths.length === 0`, `cost === 200`.
  - tracé avec virage (L) à travers l'enclos → `ok`.
  - herbe aux bouts → `paths.length === 2`, `cost === 4*50 + 2*10`.
  - un bout dans l'enclos → `bridgeEnds` ; tracé sans enclos → `bridgeNoEnclosure` ; décoration `lavaRock` sur le tracé → `bridgeBlocked` avec cette case dans `bad` ; décoration `reeds` (`low`) → `ok` ; abri sous le tracé → `bridgeBlocked`.
  - `bridgeHeightAt` : 3.9 au milieu d'une case de pont ; 0 au bord extérieur de la case d'escalier ; 3.9 / 2 au milieu de la case d'escalier ; 0 sur une case lointaine.
- [ ] **Step 2 :** `npx vitest run tests/sim/bridge.test.js` → FAIL.
- [ ] **Step 3 :** implémenter `src/sim/bridge.js` et les trois valeurs de `balance.js`.
- [ ] **Step 4 :** `npx vitest run` → PASS.
